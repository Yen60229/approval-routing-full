# 設計文件：涵蓋率檢查 A 區改為跨單位批次建立起點

**日期**：2026-08-19
**狀態**：待實作
**影響範圍**：`tools/05-coverage-check.js` A 分頁（未設定起點），寫入 App 686（員工起點對照表）

---

## 一、問題陳述

A 區「未設定起點」目前的操作是：用單位下拉篩選 → 全選 → 在底部選**一個**起點角色 → 建立。

起點角色只能選一個，所以跨多個單位的人必須一個單位做一輪。單位一多，HR 要重複「篩選→全選→選角色→送出」幾十次，非常耗時。

**目標**：一次處理多個不同單位的人。

---

## 二、關鍵前提

### 2.1 同單位同職稱的人，起點角色必然相同

685 的 `role_name` 是計算欄位 `unit_name + title_level`（見 `docs/對話脈絡.md` §9.1）。
員工的起點角色 = 他自己那一關 = 他的單位 + 他的職稱。

因此**以 `(單位, 職稱)` 分組後，每組只需要選一次角色**。幾百人通常會收斂成幾十組。

### 2.2 配對用欄位相等，不做字串處理

685 記錄上 `unit_name` 與 `title_level` 是各自獨立的欄位，配對直接比這兩欄即可，
**不需要去拆 `role_name` 字串**——這同時避開 `CLAUDE.md` 鐵律「禁止接觸組織名稱」。

Jimmy 已確認：kintone 組織設定的職稱與 685 的 `title_level` 六選項**目前是吻合的**。

### 2.3 686 是一人一筆起點

同一個人絕不能建出兩筆起點記錄。分組必須互斥。

---

## 三、設計

### 3.1 人員分流

A 區的人（`model.noEntry`）分成兩塊：

| 塊 | 條件 | 呈現 |
|---|---|---|
| **主表** | 剛好一個單位、剛好一個職稱 | 依 `(單位, 職稱)` 分組，一組一列 |
| **例外區** | 多單位、多職稱，或單位／職稱空白 | 一人一列，自己選 |

兩塊互斥，同一個人只會出現在其中一邊的一列，天然不會重複建。

### 3.2 自動配對

對主表每一組的 `(單位, 職稱)`，在 685 **啟用中**角色裡找：

```
role.unitName === 組的單位 && role.titleLevel === 組的職稱
```

| 結果 | 處理 |
|---|---|
| 找到（1 筆或多筆同名） | 帶入該角色；多筆同名時取**記錄編號最小**者的 `role_id` |
| 找不到 | 該列標紅、下拉留空、**checkbox 停用**，需 HR 手動選 |

例外區不做自動配對（單位／職稱本來就不明確），一律手選。

> 同名角色有多筆是正常的（一筆記錄只掛一人，見 §9.5）。取最小記錄編號只是為了
> 每次執行結果一致；`entry_role_id` 存哪個 role_id 不影響業務語意（見 §9.2）。

### 3.3 畫面

A 分頁改成：

```
[搜尋框] [☑ 只看尚未指定]                已指定 12/18 組・涵蓋 143 人
┌──────────────────────────────────────────────────────────┐
│ ☑  單位              職稱   人數   起點角色                 │
│ ☑  海運貨物（KHH）   課員    23    [海運貨物（KHH）－課員 ▾] │
│ ☑  海運貨物（KHH）   課長     3    [海運貨物（KHH）－課長 ▾] │
│ ☐  資訊部            專員     5    [（未配對，請選擇）   ▾] │← 紅底
└──────────────────────────────────────────────────────────┘
── 兼任多單位／多職稱（4 人）──
│ ☑  王小明  a001  海運貨物（KHH）、業務部  課長  [        ▾] │
                              [ 一次建立 143 筆起點設定 ]
```

- **移除**原本的「單位」篩選下拉（分組後列數已大幅減少），只留搜尋框
- 搜尋同時比對單位、職稱、以及例外區的姓名／帳號
- 「只看尚未指定」用來快速收斂到待處理的列
- 每列的角色下拉沿用現有可打字搜尋的選擇器（`buildRoleCombo`）
- 人數欄 hover 顯示該組的人員姓名（tooltip），送出前可確認組內是誰

### 3.4 寫入

送出時：

1. 收集所有**已勾選且已指定角色**的列
2. 展開成 `{ code, roleId }` 清單（主表一組展開成該組全部的人）
3. 對 `code` 去重當保險——**一人只會建一筆**
4. 依 `WRITE_BATCH`（100）分批 POST 到 686
5. 完成後 `rescan()`

確認視窗須說明：**幾組／幾人**會建立，以及**幾組因未指定角色被略過**。

### 3.5 防呆

| 情境 | 處理 |
|---|---|
| 未指定角色的列 | checkbox 停用，勾不到，不可能送出 |
| 同一人出現兩次 | 分組互斥 + 送出前 code 去重，雙重保險 |
| 選到的角色同名記錄之間 `next_role_id` 不一致 | 該列標黃提示，沿用 B 區同一套判斷 |
| 一組都沒勾 | 建立按鈕停用 |

---

## 四、不做的事（YAGNI）

- **不做模糊配對**：職稱對不上就標紅讓人選，不猜
- **不改 686 既有記錄**：A 區只處理「完全沒有起點」的人，一律是新增
- **不動 B～F 區**：本次只改 A 分頁
- **不做組內個別覆寫**：職稱特殊的人自然會自成一組，不需要在組內再挑人

---

## 五、驗收條件

1. A 分頁列出的組數 < 人數，且每組人數加總 + 例外區人數 = 原本 A 區總人數
2. 職稱與 `title_level` 吻合的組，開啟時起點角色已自動帶入
3. 找不到對應角色的組標紅且勾不動
4. 勾多個不同單位的組 → 按一次建立 → 686 一次生出全部記錄，每人剛好一筆
5. 建立後重新掃描，這些人不再出現在 A 區
6. 搜尋框可同時命中單位、職稱、例外區的姓名與帳號
