# 表單接入與測試手冊

把一張申請表單接上簽核引擎。先用測試表單 **737** 跑通，再接正式表單（40～50 張都照這份做）。

- **736** 表單路由設定表：決定單子怎麼走
- **737** 測試用申請表單：實際送單的那張

欄位規格以 `docs/02` 為準，設計理由看 `docs/06`。

---

## 一、737 加欄位

「設定 → 表單」加下面這些。**欄位代碼一字不差**（adapter 認代碼，不認顯示名稱），**全部不要勾必填**。

| 欄位代碼 | 類型 | 給誰看 |
|---------|------|-------|
| `current_approvers` | 使用者選擇（多選） | 看得到、不能改；不要勾「不允許重複」 |
| `current_step` | 數值 | 隱藏 |
| `total_steps` | 數值 | 隱藏 |
| `next_state` | 文字（單行） | 隱藏 |
| `reject_state` | 文字（單行） | 隱藏 |
| `approver_chain` | 表格 | 看得到、不能改 |

表格 `approver_chain` 裡放 8 欄：

| 欄位代碼 | 類型 |
|---------|------|
| `step_no` | 數值 |
| `role_id`、`step_name`、`signing_mode`、`step_state` | 文字（單行） |
| `expected_signers`、`signed_by` | 使用者選擇（多選） |
| `signed_at` | 日期時間 |

## 二、上傳 JS

「設定 → JavaScript／CSS 自訂」，**照順序**上傳，完成後按「更新應用程式」。

| App | 由上而下 |
|-----|---------|
| 737 | `coding_tools.js` → `core/01,05,04,02,03,06` → `adapters/00-standard-adapter.js` |
| 736 | `coding_tools.js` → `core/01,05,04,02,03,06,07,09` → `apps/form-route/01-route-form.js` → `tools/10-status-generator.js` |

其他 App 的順序看 `docs/10` 第四節。

## 三、736 設路由、部署

1. 736 新增一筆：表單 App ID 填 `737`、填表單名稱、勾「啟用中」、駁回退回選「退回申請人」
2. 路由關卡加兩列：
   - 員工鏈段，簽到「部長」
   - 指定角色段，挑一個經辦角色
3. 存檔 → 回列表頁 →「部署 ▾ → 部署流程設定」→ 選 737 → 下載備份並繼續 → 部署

流程管理的狀態、按鈕、執行者**全部由產生器寫入**，不用手動設。

最後到 737 開記錄權限：**簽核者要有編輯權**（adapter 簽核時要寫欄位）。

## 四、測試

照順序做，前一項沒過就先停。

| # | 怎麼做 | 應該看到 |
|---|-------|---------|
| 1 | 737「設定 → 流程管理」 | 7 個狀態：草稿、簽核中、經辦人確認中、會簽中、駁回、核決、作廢。「簽核中」的同意、駁回各 4 條，含一條「簽核中 → 簽核中」。簽核者畫面「同意」只有**一顆** |
| 2 | 用 686 有設起點的帳號新增一筆、存檔、按「送出」 | 簽核流程表格長出幾列；狀態「簽核中」，執行者是第 1 關 |
| 3 | 每關的人依序按「同意」 | 狀態維持「簽核中」、執行者換下一關；到經辦關變「經辦人確認中」；最後變「核決」 |
| 4 | 單停在第 2 關時，去 685 換掉第 2 關的簽核者，回來重新整理 | 執行者自動變新的人（頁面會自動重整一次，正常） |
| 5 | 任一關按「駁回」，申請人再按「再申請」 | 駁回：回到申請人、關卡變 0；再申請：回草稿，可重送 |
| 6 | 736 把指定角色段改「全員會簽」（角色掛 2 人以上的群組），再送一張 | 停在「會簽中」，最後一個人簽完才往下 |

第 1 項如果「同意」出現好幾顆，代表 kintone 不吃這個設計，要回報。第 4 項是這個專案最重要的功能。

## 五、出問題先看這裡

| 狀況 | 通常是 |
|------|--------|
| 簽核流程表格是空的 | 欄位沒加齊，F12 Console 會寫缺哪幾個 |
| 跳「無法建立簽核流程」 | 申請人在 686 沒有起點，或某一關沒有簽核者（訊息會寫第幾關） |
| 按同意跳「沒有權限」 | 記錄權限沒開編輯給簽核者 |
| 按同意狀態沒動，或直接跳核決 | `next_state` 沒寫對，看 Console |
| 執行者是空的 | 那關的角色在 685 沒有簽核者，或群組是空的 |
| 頁面一直重整 | 執行者補正失敗，連兩次會跳警告；把 Console 訊息回報 |
| 會簽第一個人簽完就跳關 | 「是不是最後一個簽」判斷有問題，回報 |
| 部署失敗、訊息提到狀態 | 還有單子停在要改的狀態上，kintone 不准改 |
| 部署後按鈕沒變 | 部署還在跑，等一下再重整，不要重按 |
