## 二、建立測試表單的欄位

新建一個 App（例如「簽核測試單」），除了你自己要的內容欄位（申請事由、金額之類）之外，加上以下欄位。

> ⚠️ **欄位代碼必須一字不差。** adapter 是同一支 JS 掛在所有表單上，它認的是**欄位代碼**不是顯示名稱。顯示名稱隨便取中文都可以，代碼錯一個字母 adapter 就整支停用。

### 主表欄位（6 個）

| 欄位代碼 | kintone 欄位類型 | 顯示名稱建議 | 使用者看得到嗎 |
|---------|-----------------|------------|--------------|
| `approver_chain` | 表格（子表格） | 簽核鏈 | 詳情頁可見，唯讀 |
| `current_approvers` | 使用者選擇（**多選**） | 目前簽核者 | 可見，唯讀 |
| `current_step` | 數值 | 目前關卡 | 建議隱藏 |
| `total_steps` | 數值 | 總關卡數 | 建議隱藏 |
| `next_state` | 文字（單行） | 下一站 | 隱藏 |
| `reject_state` | 文字（單行） | 駁回去向 | 隱藏 |

### 子表格 `approver_chain` 內的 8 欄

| 欄位代碼 | kintone 欄位類型 | 裝什麼 |
|---------|-----------------|--------|
| `step_no` | 數值 | 第幾關 |
| `role_id` | 文字（單行） | 該關的角色代碼 — 跑到時拿它去角色表查現在是誰 |
| `step_name` | 文字（單行） | 角色名稱，給人看的 |
| `expected_signers` | 使用者選擇（多選） | 送單當下解析出來的人（快照） |
| `signing_mode` | 文字（單行） | 任一人簽 / 全員會簽 |
| `step_state` | 文字（單行） | 這關要停在哪個狀態 |
| `signed_by` | 使用者選擇（**多選**） | 實際簽的人。全員會簽會累加多人，不能是單選 |
| `signed_at` | 日期時間 | 簽核時間 |

> ⚠️ **這些欄位一律不要勾「必填」。** 它們是 adapter 在儲存當下才填的，設成必填會在填進去之前就被 kintone 擋下來。`current_approvers` 也不要設「禁止重複值」。

### 上傳 JS（順序不能亂）

```
coding_tools
core/01-config.js
core/05-vendor.js
core/04-utils.js
core/02-api-client.js
core/03-chain-builder.js
core/06-route-engine.js
adapters/00-standard-adapter.js
```

申請 App 不需要 `core/07-role-picker.js`（那是路由表的下拉元件用的）。

## 三、設定路由與部署流程

1. 上傳 736 的 JS：`coding_tools` → `core/01,05,04,02,03,06,07` → `apps/form-route/01-route-form.js` → `tools/10-status-generator.js`
2. 在 736 新增一筆記錄：**表單 App ID** 填測試表單的 App ID、**表單名稱**隨意、勾**啟用中**
3. 路由關卡子表格加一列：段類型選「員工鏈段」、簽到職稱為止選「部長」
4. 再加一列：段類型選「指定角色段」、指定角色挑一個經辦類的角色
5. 儲存後回清單頁，按 **「部署流程設定」** → 選這張表單 → 下載備份並繼續 → 到 kintone 畫面確認 → 部署

> 流程管理的狀態、動作、執行者設定**全部由產生器寫入**，你不需要在「流程管理」畫面手動設任何東西。

## 四、測試計畫

照順序做。前面的沒過，後面的沒有意義。

### TEST 1 — 狀態圖長對了嗎

部署完成後，到測試表單的「表單設定 → 流程管理」看一眼。

**應該看到**：7 個狀態 — 草稿、簽核中、經辦人確認中、會簽中、駁回、核決、作廢。
點「簽核中」，動作清單裡「同意」有 4 條、「駁回」有 4 條（各自條件不同），
其中**包含一條「簽核中 → 簽核中」的自迴圈**。

**如果**簽核者畫面上冒出好幾顆「同意」按鈕（而不是一顆），代表 kintone 不接受
同一來源狀態的同名動作 → 回報，改成不同名字即可。

### TEST 2 — 送出一張單

用一個**有設起點角色**的帳號建一筆記錄，填好內容按儲存。

**儲存後**：簽核鏈子表格自動長出幾列（每列一關）、目前簽核者顯示第 1 關的人、狀態是「草稿」。
**按「送出」後**：狀態變「簽核中」，執行者是第 1 關的人。

**如果**跳出「無法建立簽核鏈」→ 那個帳號在 686 沒有起點角色，或鏈上某一關沒有簽核者。
訊息會指出是哪一關。

### TEST 3 — 自迴圈（新模型的核心）

用第 1 關的人登入按「同意」。這張單的員工鏈段有好幾關都是主管。

**狀態仍然是「簽核中」**（沒有變成別的名字），但**執行者換成第 2 關的人**、目前關卡變成 2。
一路同意下去，走到指定角色段那一關時，狀態才變成**「經辦人確認中」**。
最後一關同意 → **「核決」**，目前簽核者清空。

**如果**按了同意狀態卻沒動、或直接跳到核決 → 是 `next_state` 沒被正確寫入。
開 F12 Console 看有沒有錯誤。

### TEST 4 — 即時解析（整個專案存在的理由）

讓一張單停在第 2 關。到 685 把第 2 關那個角色的**簽核者換成另一個人**，儲存。
回到那張在途單重新整理。

**執行者自動變成新的人**，新的人看得到「同意」按鈕。
這是靠 `detail.show` 安全網 + 更新執行者 API 做到的，頁面會自動重整一次。

**如果**頁面一直重整不停 → 補正失敗但沒被偵測到。連續兩次後會跳警告並停手；
把 Console 訊息回報。

### TEST 5 — 駁回與再申請

任一關按「駁回」→ 狀態變**「駁回」**，執行者是**申請人**，目前關卡歸 0。
申請人改完按**「再申請」**→ 回「草稿」，可以再送一次（會重算整條鏈）。

### TEST 6 — 全員會簽

在 736 把某個指定角色段的「簽核模式」改成**全員會簽**，重新送一張單。
那個角色要掛**群組**（群組裡有 2 人以上）。

走到那一關時狀態是**「會簽中」**。
第一個人按同意 → **狀態不變、關卡不動**，只有簽核鏈的 `signed_by` 多一個人。
最後一個人按同意 → 才前進到下一關。

**如果**第一個人按下去就跳關 → 判定「是不是最後一簽」的邏輯有問題，回報。

## 五、出問題先看這裡

| 症狀 | 八成是 |
|------|--------|
| 什麼都沒發生，鏈也沒長出來 | 6 個規約欄位有缺。F12 Console 會印出「沒有埋齊 adapter 規約欄位」並列出需要哪些 |
| 簽核者按同意跳「無權限」 | 記錄權限沒開給簽核者。kintone 規定：`proceed` 內寫欄位需要該筆記錄的編輯權 |
| 部署失敗，訊息提到狀態 | 目標狀態上還有在途單。kintone 不准刪除／改動「還有記錄停在上面」的狀態 |
| 執行者是空的 | 那一關的角色在 685 沒有簽核者，或群組是空的 |
| 部署後按鈕沒變 | 部署還在跑（PROCESSING）。等一下重整，不要重按 |
