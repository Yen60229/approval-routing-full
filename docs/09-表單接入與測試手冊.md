# 表單接入與測試手冊

把一張申請表單接上簽核引擎，再逐項確認有沒有正常運作。40～50 張表單都照這份做。

第一次做的時候，先拿一張新建的測試表單跑完整份，確認沒問題再接正式表單。
目前進度看 `Phase進度追蹤.md`。

---

## 一、申請表單要加的欄位

除了表單本身的內容欄位（申請事由、金額等），再加下面這些。

**欄位代碼要一字不差。** 所有表單共用同一支 adapter，它認的是欄位代碼，不是顯示名稱。
顯示名稱可以隨意取，代碼錯一個字，adapter 就不會動。

### 主表（6 個）

| 欄位代碼 | 欄位類型 | 顯示名稱（參考） | 使用者看得到嗎 |
|---------|---------|----------------|--------------|
| `approver_chain` | 表格 | 簽核流程 | 看得到，不能改 |
| `current_approvers` | 使用者選擇（**多選**） | 目前簽核者 | 看得到，不能改 |
| `current_step` | 數值 | 目前關卡 | 建議隱藏 |
| `total_steps` | 數值 | 總關卡數 | 建議隱藏 |
| `next_state` | 文字（單行） | 下一步 | 隱藏 |
| `reject_state` | 文字（單行） | 駁回去向 | 隱藏 |

### 表格 `approver_chain` 裡的 8 欄

| 欄位代碼 | 欄位類型 | 放什麼 |
|---------|---------|--------|
| `step_no` | 數值 | 第幾關 |
| `role_id` | 文字（單行） | 這一關的角色代碼，跑到時用它去查現在是誰 |
| `step_name` | 文字（單行） | 關卡名稱 |
| `expected_signers` | 使用者選擇（多選） | 送單當下查到的人 |
| `signing_mode` | 文字（單行） | 任一人簽或全員會簽 |
| `step_state` | 文字（單行） | 這一關停在哪個狀態 |
| `signed_by` | 使用者選擇（**多選**） | 實際簽的人，全員會簽會有好幾個 |
| `signed_at` | 日期時間 | 簽核時間 |

**這些欄位都不要勾「必填」**，它們是 adapter 存檔時才填的，設成必填會在填之前就被擋下。
`current_approvers` 也不要勾「不允許重複的值」。

### 上傳 JS（照這個順序）

```
coding_tools.js
core/01-config.js
core/05-vendor.js
core/04-utils.js
core/02-api-client.js
core/03-chain-builder.js
core/06-route-engine.js
adapters/00-standard-adapter.js
```

申請表單不需要 `core/07`～`core/09`，那些是給設定表和工具用的。

## 二、設定路由、部署流程

1. 確認 736 已經照 `docs/10` 第四節上傳好 JS
2. 在 736 新增一筆：「表單 App ID」填這張表單的 App ID，填表單名稱，勾「啟用中」
3. 路由關卡加一列：段類型選「員工鏈段」，簽到職稱選「部長」
4. 再加一列：段類型選「指定角色段」，指定角色挑一個經辦的角色
5. 存檔，回列表頁，按「部署 ▾ → 部署流程設定」，選這張表單 → 下載備份並繼續 → 到 kintone 畫面確認 → 部署

流程管理的狀態、動作、執行者，**全部由產生器寫入**，不用到「流程管理」畫面手動設定。

## 三、測試

照順序做，前面沒過的話後面不用測。

### 測試 1：流程設定對不對

部署完，到表單的「設定 → 流程管理」看：

- 7 個狀態：草稿、簽核中、經辦人確認中、會簽中、駁回、核決、作廢
- 點「簽核中」，「同意」有 4 條、「駁回」有 4 條（條件各不同），其中有一條是「簽核中 → 簽核中」

**要特別確認**：簽核者畫面上「同意」只有**一顆**。如果出現好幾顆，代表 kintone 不接受同名動作，要回報改設計。

### 測試 2：送出一張單

用一個在 686 有設起點的帳號新增一筆，填好內容存檔。

- 存檔後：簽核流程表格自動長出幾列，目前簽核者是第 1 關的人，狀態是「草稿」
- 按「送出」後：狀態變「簽核中」，執行者是第 1 關的人

如果跳出「無法建立簽核流程」：這個帳號在 686 沒有起點，或某一關沒有簽核者。訊息會寫是哪一關。

### 測試 3：一直在「簽核中」往下走

用第 1 關的人登入，按「同意」。

- 狀態還是「簽核中」，但執行者換成第 2 關的人，目前關卡變 2
- 一路同意下去，走到指定角色那關時，狀態變「經辦人確認中」
- 最後一關同意後變「核決」，目前簽核者清空

如果按了同意狀態沒動，或直接跳到核決：`next_state` 沒寫對。按 F12 看 Console 有沒有錯誤。

### 測試 4：中途換人（這個專案最重要的功能）

讓一張單停在第 2 關。去 685 把第 2 關的簽核者換成另一個人，存檔。回到那張單，重新整理。

- 執行者自動變成新的人，新的人看得到「同意」
- 頁面會自動重整一次，這是正常的

如果頁面一直重整：補正失敗。連續兩次後會跳警告停下來，把 Console 的訊息回報。

### 測試 5：駁回、再申請

- 任一關按「駁回」：狀態變「駁回」，執行者是申請人，目前關卡變 0
- 申請人改完按「再申請」：回到「草稿」，可以再送一次（會重新算整條流程）

### 測試 6：全員會簽

在 736 把指定角色那一段的簽核模式改成「全員會簽」，那個角色要掛群組（群組裡至少 2 人），重新送一張單。

- 走到那一關，狀態是「會簽中」
- 第一個人按同意：狀態不變、關卡不動，`signed_by` 多一個人
- 最後一個人按同意：才往下一關

如果第一個人按下去就跳關：判斷「是不是最後一個簽」的地方有問題，回報。

## 四、出問題先看這裡

| 狀況 | 通常是 |
|------|--------|
| 什麼都沒發生，簽核流程表格是空的 | 6 個欄位沒加齊。Console 會寫缺哪幾個 |
| 簽核者按同意，跳「沒有權限」 | 記錄權限沒開給簽核者。adapter 要寫欄位，簽核者需要編輯權 |
| 部署失敗，訊息提到狀態 | 還有單子停在要改的狀態上。kintone 不准改有單子停著的狀態 |
| 執行者是空的 | 那一關的角色在 685 沒有簽核者，或群組是空的 |
| 部署後按鈕沒變 | 部署還在跑。等一下再重新整理，不要重按 |
