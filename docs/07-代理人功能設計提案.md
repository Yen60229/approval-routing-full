# 代理人功能

主管休假、出差時，讓別人代簽。

- 狀態：**設計談定，還沒做**。等表單路由（`docs/06`）試點跑穩了再做
- 談定的事（2026-07-06）：代理期間，原本的簽核者和代理人**都可以簽**

Jimmy 的需求：

> 較高層級能代理較低層級即可，同仁不用都告知 IT 修改，可以自己跑需求單、較高層級主管核可後就更改人員；代理結束或同仁休假回來，要再自行回來報到更換回原本的人員。

---

## 一、做法：查簽核者時多看一張代理表，不改任何資料

整個系統本來就是「跑到那一關才查是誰」。代理只是在查的時候多看一眼：這個人今天有沒有人代理？有的話，把代理人也加進來。

```
查這一關是誰        → [原簽核者]
有人在代理期間      → [原簽核者] + [代理人]，兩個都能簽
```

好處：

- **到期自動失效**。每次都用「今天」判斷，代理人忘了解除也不會留著權限。回來報到只是提前結束，不是唯一的保險。
- **在途的單馬上生效**。核可後，下一關開始就會用到代理人，不用回頭改已經送出的單。
- **不動任何資料**。角色表、群組、單子上的簽核鏈都不改，代理結束就自然恢復，不用「換回來」。

---

## 二、新增一張表：代理設定表

| 欄位代碼 | 顯示名稱 | 類型 | 必填 | 說明 |
|---------|---------|------|:----:|------|
| `principal_user` | 被代理人 | 使用者選擇（單選） | ✓ | 休假或出差的人 |
| `delegate_user` | 代理人 | 使用者選擇（單選） | ✓ | 代簽的人 |
| `start_date` | 開始日 | 日期 | ✓ | 含當天 |
| `end_date` | 結束日 | 日期 | ✓ | 含當天 |
| `scope` | 代理範圍 | 單選 | ✓ | 先固定「全部表單」，欄位先建好，以後要分表單不用改表 |
| `reason` | 事由 | 多行文字 | | 給核可的主管看 |

不設「啟用中」欄位。有沒有生效只看兩件事：流程狀態是「已核可」，而且今天在起訖日之間。兩套開關容易互相打架。

### 這張表自己的核可流程

用 kintone 原生的流程管理，一關就好：

```
申請中 ─主管核可→ 已核可 ─提前結束→ 已結束
   └──撤回→ 已撤回
```

- 這張表不用自己的簽核引擎，只有一關，而且會變成自己依賴自己。處理人直接設較高層級主管的群組。
- 「提前結束」讓被代理人和代理人本人都可以按。不按也沒關係，過了結束日就自動失效。

---

## 三、檢查「較高層級代理較低層級」

送出時檢查：

1. 層級高低看 685 `title_level` 下拉選項的排列順序。順序由 IT 在後台維護，程式執行時讀取，不寫死。
2. 從 685 找出被代理人和代理人各自掛在哪些角色上，取最高的職稱。
3. 代理人的層級要大於或等於被代理人，不符合就擋下。

**刻意放寬的地方**：代理人可能不在任何角色裡（例如新主管還沒加進群組），這時查不到層級，就**放行**，靠主管核可把關。
做得太死的話，組織調整期間反而要找 IT，違背「不用告知 IT」的初衷。

## 四、接進引擎

```
ApiClient 新增 getActiveDelegations()
  → 被代理人 → 代理人 的對照表
  條件：流程狀態 = 已核可，而且開始日 <= 今天 <= 結束日
  快取 60 秒

查簽核者時套用 applyDelegation(簽核者名單)
  → 原名單 + 有代理的人的代理人（去重）
```

套在兩個地方：

| 位置 | 目的 |
|------|------|
| adapter 設定執行者時（按流程按鈕、詳情頁補正） | 真正決定誰能簽 |
| 送單時組簽核鏈 | 讓申請人在子表格上看到這關有代理人 |

---

## 五、使用者會怎麼用

1. 要休假的人開代理設定表，填被代理人、代理人、起訖日、事由，送出
2. 主管在 kintone 收到通知，按「主管核可」
3. 代理期間，輪到被代理人的關卡，代理人也會出現，兩個人都能簽
4. 提前回來：本人或代理人按「提前結束」
5. 或者什麼都不做，過了結束日自動失效

HR 和 IT 都不用介入。HR 手冊之後補一頁這個流程。

## 六、還沒定的事

| 情況 | 說明 | 目前打算 |
|------|------|---------|
| 連鎖代理（A 代理 B，A 又休假由 C 代理） | 只套一層，C 不會接到 B 的關卡 | 先不支援，實務很少見 |
| 同一個人同時有兩筆代理 | 兩個代理人同時生效 | 允許，送出時提示重疊 |
| 代理人本來就在同一關 | 去重後沒差 | 不用處理 |
| 單子已經停在那一關，代理才核可 | 那一關的執行者已經設好了 | 詳情頁補正是即時查的，如果補正也套代理，有人打開這張單時就會補上。實作時確認 |

---

## 七、什麼時候做

表單路由的 adapter 上線、試點跑穩之後。代理是掛在 adapter 設定執行者的地方，adapter 還沒上線就沒地方掛。

要做的事：建表、表單 JS（層級檢查）、接進 ApiClient 和 adapter。
