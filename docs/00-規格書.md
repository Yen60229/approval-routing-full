# 規格書

簽核路由引擎的整體架構。欄位細節看 `02-欄位代碼對照表.md`，設計理由看 `對話脈絡.md`。

- 版本 2.0（2026-10-28 依現況整理）

---

## 1. 目標

取代舊系統「用組織名稱 + 職稱推算簽核者」的做法，改成**用資料表決定誰簽**。
組織怎麼變動，都只改資料，不改程式。

| 項目 | 設定 |
|------|------|
| 定位 | 共用模組，所有申請 App 掛同一支 adapter 就能接入 |
| 上線方式 | 先拿測試表單試點，再全面取代舊系統 |
| 簽核者 | 重要關卡用群組，其他指定個人 |
| 稽核紀錄 | 由各 App 既有的簽核紀錄外掛負責，本系統不重做 |
| 裝置 | 電腦版完整功能，手機只顯示 |
| 規模 | 500+ 員工、80+ 角色、40～50 張申請表單 |

---

## 2. 設計原則

**不做的事**

- 不處理組織名稱字串
- 不用 `case '課長'/'次長'/'部長'` 判斷職稱
- 不把特例寫死在程式裡
- 不重複呼叫 `kintone.app.record.get()`

**改用的做法**

- 簽核鏈用「每個角色記下一關是誰」串起來，插一關只改 1～2 筆
- 員工只知道自己的起點角色，不直接綁定任何簽核者，換人只改角色表
- 單子上記的是角色，**跑到那一關才去查現在是誰**
- 群組讓 IT 在後台換人就全面生效
- API 結果有快取，不重複呼叫
- 所有事件都包在 `safeHandler` 裡，錯誤統一用 SweetAlert2 顯示

## 3. 架構

```
維護的人
  IT：kintone 群組成員、表單路由設定（736）
  HR：角色定義表（685）、員工起點對照表（686）
        ↓
資料
  685 角色定義表       約 80 筆，每個角色是誰、下一關是誰
  686 員工起點對照表   約 500 筆，每個員工從哪個角色開始
  736 表單路由設定表   每張申請表單走哪幾段
  approver_chain       放在每個申請 App 裡的子表格，記這張單的簽核鏈
        ↓
引擎（core/）
  建簽核鏈、依路由展開、跑到時查簽核者
        ↓
申請 App
  掛 adapters/00-standard-adapter.js，加 6 個規約欄位
  流程管理用 tools/10 一鍵部署的標準 7 個狀態
```

### 3.1 一張單怎麼跑

| 時間點 | 做什麼 |
|--------|--------|
| 申請人按「送出」 | 依 736 的路由算出整條簽核鏈，存進子表格（存角色和當下的簽核者） |
| 進入某一關 | 即時查這一關現在是誰，設成執行者；同時算好按「同意」「駁回」後要去哪個狀態 |
| 簽核者按「同意」 | 依下一個狀態決定往下走；全員會簽的關卡要所有人都按才往下 |
| 中途換人 | HR 改 685 或 IT 改群組，跑到那一關就是新的人；打開詳情頁時發現執行者不對會自動補正 |

### 3.2 路由：一條鏈由幾「段」組成

736 的每一列是一段，有兩種：

- **員工鏈段**：從申請人的起點角色往上走。可以設「簽到哪個職稱為止」和「跳過哪些職稱」。
- **指定角色段**：直接指定某個角色，例如會計經辦。

兩種可以任意排，例如「員工鏈簽到課長 → 會計經辦 → 員工鏈簽到部長」。
736 沒有設定的表單，就照申請人的起點一路走到終點。

### 3.3 流程管理：固定 7 個狀態

| 狀態 | 誰處理 |
|------|--------|
| 草稿 | 申請人 |
| 簽核中 | 員工鏈段的關卡（任一人簽） |
| 經辦人確認中 | 指定角色段的關卡（任一人簽） |
| 會簽中 | 要全員會簽的關卡 |
| 駁回 | 申請人修改後再送 |
| 核決 | 結束 |
| 作廢 | 結束 |

關卡再多，都在「簽核中」上自己迴圈，每次換一個執行者。所以每張申請表單的流程設定都一樣，組織多一層也不用改。

## 4. 對外介面

所有模組都掛在 `window.ApprovalRouting` 下面。

| 名稱 | 來自 | 用途 |
|------|------|------|
| `Config` | `core/01` | App ID、欄位代碼、狀態名稱 |
| `ApiClient` | `core/02` | 讀角色、起點、路由設定（有快取） |
| `Utils` | `core/04` | `safeHandler`、提示視窗、`kintoneApi` |
| `Engine` | `core/03` | `buildChain`、`validateChain`、`simulateChain`、`reverseQuery`、`resolveHolders` |
| `buildChainForForm` | `core/06` | 依表單路由建簽核鏈（adapter 用這個） |
| `RolePicker` | `core/07` | 可搜尋的角色下拉 |
| `Directory` | `core/08` | 後台的使用者、組織、職務 |
| `ToolRegistry` | `core/09` | 工具按鈕註冊 |
| `ChainPreview` | `apps/role-definition/04` | 簽核流程預覽，`tools/08` 也用 |

名稱裡有 `Internals` 的（例如 `CoverageInternals`）只給測試用，其他程式不要呼叫。

## 6. 命名規則

| 用途 | 規則 | 例子 |
|------|------|------|
| 主鍵 | 簡短英文 | `role_id` |
| 顯示名稱 | `*_name` | `role_name` |
| 使用者選擇 | 動詞或角色 | `holder_user` |
| 群組選擇 | `*_group` | `holder_group` |
| 指向別筆的代碼 | `*_id` | `next_role_id`、`entry_role_id` |
| 是非 | `is_*` | `is_active`、`is_chain_end` |
| 時間 | `*_at` | `signed_at` |
| 子表格 | 名詞 | `approver_chain` |

角色代碼格式是 `ROLE_0001`，4 位數流水號，由程式產生。

## 9. 風險

| 風險 | 怎麼處理 |
|------|---------|
| 一次切換全部表單風險太大 | 先用測試表單試點，P9 準備應變指南 |
| 流程管理 API 有文件沒寫的限制 | 部署前由產生器先檢查，每遇到一條就加一條檢查 |
| 執行者沒有跟著換 | 用更新執行者 API 設定，詳情頁再補正一次 |
| 角色表設錯（繞圈、中斷、沒人簽） | 健康檢查和未設定名單定期跑 |
| 角色多、鏈深時預覽變慢 | 角色表整包快取 |
| HR 用 kintone 的預覽功能會掉資料 | 手冊裡寫清楚，不要用預覽 |
