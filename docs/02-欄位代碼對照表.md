# 欄位代碼對照表

所有 App 的欄位都列在這裡。程式裡的欄位代碼集中在 `core/01-config.js`，兩邊要一致。
kintone 上新增或改了欄位，記得兩邊一起改。

---

## 685　角色定義表

一筆記錄 = 一個關卡的一位簽核者。同一關有 3 個人可以簽，就建 3 筆同名記錄。

| 欄位代碼 | 顯示名稱 | 類型 | 必填 | HR 看得到 | 說明 |
|---------|---------|------|:----:|:--------:|------|
| `role_id` | 角色代碼 | 文字 | ✓（唯一） | ✗ | 程式自動產生，格式 `ROLE_0001` |
| `role_name` | 角色名稱 | 計算 | | ✓ | 由單位和職稱自動組成。**程式不能寫入這一欄** |
| `unit_name` | 單位 | 下拉 | ✓ | ✓ | 選項由 IT 維護，程式執行時讀取，不寫死 |
| `title_level` | 職稱 | 下拉 | ✓ | ✓ | 固定六個選項 |
| `holder_type` | 簽核者類型 | 單選 | ✓ | ✓ | 指定群組／指定個人，預設指定群組 |
| `holder_group` | 簽核者（群組） | 群組選擇 | 選群組時必填 | ✓ | |
| `holder_user` | 簽核者（個人） | 使用者選擇 | 選個人時必填 | ✓ | **只能放一個人** |
| `next_role_id` | 下一關 | 文字 | | ✗ | 畫面上是搜尋下拉 |
| `is_chain_end` | 是否為終點 | 核取方塊 | | ✓ | 選項「是終點」 |
| `signing_mode` | 簽核模式 | 單選 | ✓ | ✓ | 任一人簽／全員會簽，預設任一人簽 |
| `is_active` | 啟用狀態 | 核取方塊 | | ✓ | 選項「啟用中」，預設勾選 |
| `chain_preview` | 簽核流程預覽 | 空白欄位 | | ✓ | 程式在這裡畫預覽和下拉 |

**「下一關已設定」的意思**：`next_role_id` 有值，或勾了「是終點」。兩個都沒有就是流程中斷。

## 736　表單路由設定表

由 IT 或表單窗口維護，不是 HR。所以這張表不用隱藏代碼欄位。

### 主表

| 欄位代碼 | 顯示名稱 | 類型 | 必填 | 說明 |
|---------|---------|------|:----:|------|
| `form_app_id` | 表單 App ID | 數值 | ✓（唯一） | 申請 App 的 App ID |
| `form_name` | 表單名稱 | 文字 | ✓ | 例如「採購申請單」 |
| `is_active` | 啟用狀態 | 核取方塊 | | 沒啟用的話，這張表單照申請人起點走到終點 |
| `route_steps` | 路由關卡 | 子表格 | ✓ | 見下表 |
| `reject_target` | 駁回退回 | 單選 | ✓ | 退回申請人／退回上一關，預設退回申請人 |
| `cancel_groups` | 可作廢群組 | 群組選擇 | | 只有這些群組能按「作廢」。沒設就不產生作廢動作 |
| `deployed_at` | 上次部署時間 | 日期時間 | | 產生器自動回寫 |
| `deployed_hash` | 部署版本 | 文字 | | 產生器自動回寫，用來看標準流程改版後這張表單有沒有重新部署 |
| `max_depth` | 最大關卡數 | 數值 | | **已停用**，狀態改成自己迴圈後就用不到了。欄位留著是為了不掉舊資料 |

### 子表格 `route_steps`

每一列是一段，照 `step_no` 的順序執行。

| 欄位代碼 | 顯示名稱 | 類型 | 用在哪種段 | 說明 |
|---------|---------|------|-----------|------|
| `step_no` | 順序 | 數值 | 兩種都用 | 要嘛全部留空（照畫面順序），要嘛全部填而且不重複 |
| `segment_type` | 段類型 | 單選 | | 員工鏈段／指定角色段 |
| `stop_at_title_level` | 簽到哪個職稱為止 | 下拉 | 員工鏈段 | 選項要跟 685 的 `title_level` 一樣，不一樣會跳警告 |
| `skip_title_levels` | 跳過的職稱 | 多選 | 員工鏈段 | 會經過但不用簽的職稱 |
| `role_id` | 指定角色 | 文字 | 指定角色段 | 畫面上是搜尋下拉 |
| `step_signing_mode` | 簽核模式 | 單選 | 兩種都用 | 沿用角色表／任一人簽／全員會簽 |

「簽到哪為止」決定走到哪裡停，「跳過的職稱」決定路上哪幾層不用簽。兩個可以一起用，例如「簽到部長，但不用次長簽」。

兩種段都可以設全員會簽，那幾關會停在「會簽中」。

## 申請 App 要加的欄位

每個要接入的申請 App，都要加下面這些欄位，adapter 才能運作。

### 規約欄位

| 欄位代碼 | 類型 | 說明 |
|---------|------|------|
| `approver_chain` | 子表格 | 這張單的簽核鏈，見下表 |
| `current_approvers` | 使用者選擇（多選） | 目前這一關該誰簽。主要給畫面顯示；實際的執行者由 adapter 用更新執行者 API 設定 |
| `current_step` | 數值 | 目前第幾關，0 代表還沒開始簽（草稿或駁回） |
| `total_steps` | 數值 | 總共幾關，顯示「第 3 / 5 關」用 |
| `next_state` | 文字 | 按「同意」後要去哪個狀態 |
| `reject_state` | 文字 | 按「駁回」後要去哪個狀態 |

`next_state` 和 `reject_state` 是給流程管理的分歧條件看的。狀態不再編號，光看「簽核中」不知道下一關是誰，
所以 adapter 在進入每一關時就先算好寫進去。kintone 判斷分歧條件時，看的是按下按鈕**之前**的值。

### 子表格 `approver_chain`

| 欄位代碼 | 類型 | 說明 |
|---------|------|------|
| `step_no` | 數值 | 第幾關 |
| `role_id` | 文字 | 這一關的角色代碼 |
| `step_name` | 文字 | 顯示用的關卡名稱 |
| `expected_signers` | 使用者選擇（多選） | 送單當下查到的簽核者 |
| `signing_mode` | 文字 | 這一關是任一人簽還是全員會簽 |
| `step_state` | 文字 | 這一關停在哪個狀態：簽核中、經辦人確認中或會簽中。送單時就記下來，之後路由改了，在途的單照原樣跑完 |
| `signed_by` | 使用者選擇（多選） | 實際簽的人。全員會簽會有好幾個人 |
| `signed_at` | 日期時間 | 簽核時間 |

**子表格欄位的類型一定要跟上表一樣**（程式裡的 `CHAIN_FIELD_TYPES`）。adapter 是自己組好整列寫進去的，
類型不對的話，kintone 會回報 `approver_chain.value[n]` 的錯誤。

## 流程管理的 7 個狀態

全公司統一，每個申請 App 都一字不差，由 `tools/10` 一鍵部署。

| 狀態 | 執行者 | 說明 |
|------|--------|------|
| 草稿 | 不設（第一個狀態只能這樣） | 申請人編輯，按「送出」 |
| 簽核中 | `current_approvers`，任一人 | 員工鏈段的關卡 |
| 經辦人確認中 | `current_approvers`，任一人 | 指定角色段的關卡 |
| 會簽中 | `current_approvers`，全員 | 全員會簽的關卡 |
| 駁回 | 申請人 | 修改後按「再申請」回草稿 |
| 核決 | 無 | 結束 |
| 作廢 | 無 | 結束 |

動作：送出、同意、駁回、再申請、作廢。簽核者只會看到「同意」和「駁回」兩顆。

「會簽中」要獨立出來，是因為 kintone 的「任一人」或「全員」是每個狀態固定的，不能每張單不一樣。

### 申請 App 的記錄權限

adapter 要在簽核時寫欄位，所以**簽核者必須有那筆記錄的編輯權限**，這是 kintone 的規定。搭配方式：

1. 記錄權限依狀態開放：草稿時只有申請人能改，簽核中時簽核者能改
2. JS 在詳情頁把業務欄位鎖住
3. 變更履歷留紀錄（既有外掛負責）

kintone 的欄位權限沒辦法依狀態切換，所以擋不住有人故意用 API 改單。但那是舞弊，履歷查得到。

**API token 絕對不能寫在前端 JS 裡**。自訂 JS 是在使用者的瀏覽器跑的，寫進去等於公開給所有人。
