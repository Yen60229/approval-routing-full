## App 1 — 角色定義表 `role_definition`

**App ID**：**685**

| # | 欄位代碼 | 顯示名稱 | 類型 | 必填 | 唯一鍵 | 預設值 | HR 可見 | 說明 |
|:-:|---------|---------|------|:----:|:------:|--------|:-------:|------|
| 1 | `role_id` | 角色代碼 | 文字（單行） | ✓ | ✓ | （程式產生） | ✗ | 自動產生流水號 `ROLE_0001`，送出前查最大現有號碼遞增 |

| 2a | `unit_name` | 單位 | 下拉式選單 | ✓ | | | ✓ | role_name 計算來源（前段）；選項由 IT 維護，程式以 `getFormFields()` 動態載入；詳情頁隱藏 |
| 2b | `title_level` | 職稱 | 下拉式選單 | ✓ | | | ✓ | role_name 計算來源（後段）；固定六選項；詳情頁隱藏 |
| 3 | `holder_type` | 簽核者類型 | 單選按鈕 | ✓ | | 指定群組 | ✓ | 選項：指定群組 / 指定個人 |
| 4 | `holder_group` | 簽核者（群組） | 群組選擇 | 條件 | | | ✓ | holder_type=群組時必填 |
| 5 | `holder_user` | 簽核者（個人） | 使用者選擇 | 條件 | | | ✓ | holder_type=個人時必填 |
| 6 | `next_role_id` | 下一關角色代碼 | 文字（單行） | | | | ✗ | 由程式提供下拉 UI |
| 7 | `is_chain_end` | 是否為終點 | 核取方塊 | | | 不勾 | ✓ | 選項：「是終點」 |
| 8 | `signing_mode` | 簽核模式 | 單選按鈕 | ✓ | | 任一人簽 | ✓ | 選項：任一人簽 / 全員會簽 |
| 9 | `is_active` | 啟用狀態 | 核取方塊 | | | 勾選 | ✓ | 選項：「啟用中」 |
| 10 | (空白欄位) | 簽核鏈預覽 | 空白欄位 | | | | ✓ | 元素 ID = `chain_preview` |

### 版面建議

```
[unit_name (寬度 35%)] [title_level (寬度 35%)]   [is_chain_end] [is_active]
[role_name (計算欄位，自動組合 unit_name + title_level；詳情頁隱藏 unit/title)]
[holder_type (寬度 30%)]
[holder_group (寬度 50%)]           [holder_user (寬度 50%)]
[signing_mode (寬度 30%)]
[next_role_id (隱藏，由程式提供下拉 UI)]
[空白欄位 chain_preview (寬度 100%)]
[role_id (寬度 30%，程式用，由 JS 隱藏)]
```

## App 3 — 表單路由設定表 `form_route_config`

**App ID**：**待建立後補**（填入 `core/01-config.js` 的 `APP_ID.FORM_ROUTE_CONFIG`）

> **維護者是 IT／表單窗口，不是 HR。** HR 管「人與角色」（685/686），
> 表單窗口管「這張單走什麼流程」。因此本表不需要對使用者隱藏代碼欄位。

### 主表

| # | 欄位代碼 | 顯示名稱 | 類型 | 必填 | 唯一鍵 | 預設值 | 說明 |
|:-:|---------|---------|------|:----:|:------:|--------|------|
| 1 | `form_app_id` | 表單 App ID | 數值 | ✓ | ✓ | | 申請 App 的 kintone App ID；adapter 以 `kintone.app.getId()` 查此欄 |
| 2 | `form_name` | 表單名稱 | 文字（單行） | ✓ | | | 例：「採購申請單」，給維護者看 |
| 3 | `is_active` | 啟用狀態 | 核取方塊 | | | 勾選 | 選項：「啟用中」。未啟用時 adapter 走 fallback 全鏈 |
| 4 | `route_steps` | 路由關卡 | 表格（子表格） | ✓ | | | 有序，見下 |
| 5 | `max_depth` | 最大關卡數 K | 數值 | | | | **產生器算完回寫，不要人工填** |
| 6 | `cancel_groups` | 可作廢群組 | 群組選擇（多選） | | | | 產生器用：每個非終態掛「作廢」動作限定這些群組 |
| 7 | `reject_target` | 駁回退回 | 單選按鈕 | ✓ | | 退回申請人 | 選項：`退回申請人` / `退回上一關` |
| 8 | `deployed_at` | 上次部署時間 | 日期時間 | | | | 產生器回寫 |
| 9 | `deployed_hash` | 部署版本指紋 | 文字（單行） | | | | 產生器回寫；比對得出「路由改了但沒重跑產生器」 |

### 子表格 `route_steps`

| 欄位代碼 | 顯示名稱 | 類型 | 適用段類型 | 說明 |
|---------|---------|------|-----------|------|
| `step_no` | 順序 | 數值 | 兩者 | 段的執行順序 |
| `segment_type` | 段類型 | 單選按鈕 | — | 選項：`員工鏈段` / `指定角色段` |
| `stop_at_title_level` | 簽到職稱為止 | 下拉式選單 | 員工鏈段 | **選項須與 685 `title_level` 完全相同**（程式載入時比對，不一致會警告） |
| `skip_title_levels` | 跳過的職稱 | 複選框 | 員工鏈段 | 同上選項；沿鏈經過但**不列入簽核**的職稱層級 |
| `role_id` | 指定角色 | 文字（單行） | 指定角色段 | 由程式提供可搜尋下拉，畫面顯示 role_name |
| `step_signing_mode` | 簽核模式 | 單選按鈕 | 兩者 | 選項：`（沿用角色表）` / `任一人簽` / `全員會簽`。**「全員會簽」僅指定角色段可用**——原生流程的 ANY/ALL 是每個狀態靜態設定，位置浮動的員工鏈段無法指定 |

**`stop_at_title_level` 與 `skip_title_levels` 的差別**：前者決定走到哪裡**停**，後者決定路上哪幾層**不簽**。兩者可並用，例如「走到部長為止，但中間不簽次長」。

**段可任意排列**：`員工鏈段 → 指定角色段 → 員工鏈段` 是合法的——這就是「穿插經辦人」。

### 版面建議

```
[form_name (寬度 40%)]  [form_app_id (寬度 20%)]  [is_active (寬度 15%)]
[reject_target (寬度 30%)]        [cancel_groups (寬度 50%)]
[route_steps 子表格 (寬度 100%)]
[max_depth (20%)] [deployed_at (30%)] [deployed_hash (30%)]  ← 三個都是程式回寫，可設唯讀
```

### 申請 App 的記錄權限（P8）

標準 adapter 在 `process.proceed` 事件裡寫欄位，這要求**簽核者具備該筆記錄的編輯權限**（kintone 平台規則，繞不過）。安全的組合是：

1. **記錄權限用「狀態」當條件**：草稿時只有申請人可編輯；簽核中時簽核者群組可編輯
2. **JS 在 detail 頁把業務欄位設 `disabled`**
3. **變更履歷留稽核軌跡**（既有外掛負責）

⚠️ kintone 的**欄位權限無法依流程狀態切換**（記錄權限可以），所以技術上擋不住蓄意用 REST API 改單——但那已屬舞弊而非誤操作，且有履歷可查。

⚠️ **API token 絕不可寫進前端 JS**：自訂 JS 在使用者瀏覽器執行，token 等於對所有人公開。要用 token 更新記錄必須有 kintone 以外的執行環境。
