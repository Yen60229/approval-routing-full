## 四、實作：容器層 `core/09-tool-registry.js`（2026-09-01 完成）

八支工具合計約 8,000 行，硬合併風險高、效益低，所以只加一層薄容器：
每支工具照舊是自己的 IIFE，只把最後那段「建立按鈕 → 找 header → appendChild」換成註冊：

```javascript
window.ApprovalRouting.ToolRegistry.register({
  id:    'health-check',        // 唯一代號，重複註冊會覆蓋（同一支 JS 被載入兩次不會長出兩顆）
  group: 'inspect',             // inspect／query／maintain／deploy
  label: '角色表健檢',
  hint:  '循環鏈、斷鏈、孤立角色、沒有簽核者的關卡',   // 選單上的白話說明
  apps:  [APP_ID.ROLE_DEFINITION],                   // 省略＝不限 App
  run:   runAndShow,            // 進入點，可為 async
});
```

容器負責的事：

- **依 App ID 守門** — 貼錯 App 不會冒出不該有的按鈕（原本只有 3 支自己有守門）
- **統一錯誤處理** — `runTool` 會先 `Swal.close()` 再顯示錯誤，工具本體不必各寫一次 try/catch
- **選單互動** — 點分組按鈕展開、點別處或 Esc 收起；document 監聽只掛一次，換頁重畫不會累積
- **分組固定順序** — 系統健檢（紫）→ 查詢（藍）→ 維護（青綠）→ 部署（琥珀）；沒有工具的分組不出現

測試：`tests/tool-registry.test.js`（11 項，含 App 過濾、id 去重、選單展開與點擊執行、例外收斂）。

⚠️ **硬性依賴**：`core/09` 必須在所有 `tools/*.js` 之前載入 —— 工具在載入當下就會呼叫 `register`，
註冊表不在的話整支 IIFE 會炸掉。core 一律先載，照下表順序就不會有問題。
