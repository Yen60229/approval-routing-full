## 二、分組的想法

依「使用者這時候想做什麼」分，不是照檔案編號：

| 選單 | 為什麼放一起 |
|------|-------------|
| 系統健檢 | 都是掃出問題、勾選、一次修好 |
| 查詢 | 都是只看不改，輸入一個人或一個關卡，看一條流程 |
| 維護 | 主動的大量寫入，不是從問題清單出發 |
| 部署 | 只在 736、只有部署時用 |

## 三、工具怎麼掛上選單

每支工具照舊是獨立的檔案，只在最後向 `core/09-tool-registry.js` 登記：

```javascript
window.ApprovalRouting.ToolRegistry.register({
  id:    'health-check',        // 唯一代號，重複登記會覆蓋，不會多一顆
  group: 'inspect',             // inspect／query／maintain／deploy
  label: '角色表健檢',
  hint:  '流程繞圈、流程中斷、沒有人會用到的關卡',   // 選單上的說明
  apps:  [APP_ID.ROLE_DEFINITION],                 // 不寫就是每張表都出現
  run:   runAndShow,            // 按下去執行的函式，可以是 async
});
```

`core/09` 幫忙處理：

- 依 App ID 決定要不要出現，貼錯 App 也不會多出不該有的按鈕
- 錯誤統一處理，工具本身不用各自 try/catch
- 選單的開合（點別處或按 Esc 收起）
- 選單順序固定：系統健檢、查詢、維護、部署；沒有工具的選單不出現

測試在 `tests/tool-registry.test.js`。

**還沒處理的**：工具 1、5、6、8、11 各自會把 685 整張讀一次，開三個工具就讀三次。目前不慢，真的慢了再讓 `core/09` 提供共用快取。

## 四、上傳順序（以這張表為準）

| App | 順序 |
|-----|------|
| **685** | `coding_tools` → `core/01,05,04,02,03,06,07,08,09` → `apps/role-definition/01~07` → `tools/01,02,04,05,06,07,08,09,11` |
| **686** | `coding_tools` → `core/01,05,04,02,03,07,08,09` → `apps/employee-entry/01,02` → `tools/02,03,05,09,11` |
| **736** | `coding_tools` → `core/01,05,04,02,03,06,07,09` → `apps/form-route/01-route-form` → `tools/10-status-generator` |
| 申請 App | `coding_tools` → `core/01,05,04,02,03,06` → `adapters/00-standard-adapter` |

一定要遵守的順序：

- `core` 全部放在最前面
- `core/03` 在 `core/06` 前面
- `core/07` 在 `apps/*/03` 和 `apps/form-route/01` 前面
- `core/08` 在 `tools/05`、`tools/11` 前面
- `core/09` 在**所有** `tools/*` 前面，不然工具一載入就會出錯
- `apps/role-definition/04` 在 `tools/08` 前面

**這次換成選單後第一次上傳，11 支工具要全部重新上傳。** 只換一部分的話，會出現舊按鈕和新選單同時存在，或工具打不開。

## 五、畫面用字對照表

使用者是 HR 和一般同仁，**畫面上不要出現技術名詞**。新增 HR 看得到的文字前，先查這張表。
程式註解不在此限，那是寫給開發者看的。

| 技術說法 | 畫面上寫 |
|---------|---------|
| 簽核鏈 | 簽核流程 |
| 循環鏈 | 流程繞圈（永遠簽不完） |
| 斷鏈 | 流程中斷（下一關找不到） |
| 鏈過深 | 關卡太多，走不到終點 |
| 鏈上游 | 上一關 |
| 孤立角色 | 沒有人會用到的關卡 |
| 空簽核者 | 沒有指定簽核者 |
| 同名角色設定不一致 | 同一關卡的設定前後不一致 |
| `role_id` | 角色代碼 |
| `holder_type` | 簽核者類型 |
| `unit_name` / `title_level` | 單位 / 職稱 |
| `role_name` | 關卡名稱 |
| 685 | 角色定義表（685） |
| 686 | 員工起點對照表（686） |
| 736 | 表單路由設定表（736） |

刻意沒改的兩個地方：

- `tools/09`（role_id 位數對照）和 `tools/10`（部署流程設定）只有 IT 和管理者會用，保留技術用語反而清楚。
- 「員工鏈段」「指定角色段」是 736 的下拉選項值，要改得連 kintone 的選項和既有資料一起改，不能只改 JS。
