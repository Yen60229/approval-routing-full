# 簽核路由引擎（Approval Routing Engine）

kintone 上的簽核流程引擎。誰該簽，由資料表決定，不再從「組織名稱 + 職稱」去推算。
組織改名、換主管、中間多一個單位，都只要改資料，不用改程式。

---

## 從哪裡開始看

**接手開發的人**

1. `CLAUDE.md`：開發規矩、資料夾結構、合作方式
2. `docs/對話脈絡.md`：每個設計為什麼這樣做
3. `docs/Phase進度追蹤.md`：現在做到哪、接下來要做什麼
4. `docs/00-規格書.md`：整體架構

**HR**

操作手冊（`docs/01-HR維護操作手冊.md`）還在寫。在那之前，有問題直接找 Jimmy。

**IT**

- 上傳 JS 的順序：`docs/10-工具按鈕盤點與分組.md` 第四節
- 新的申請表單要接進來：`docs/09-表單接入與測試手冊.md`

---

## 資料夾

| 資料夾 | 放什麼 |
|-------|-------|
| `core/` | 所有 App 共用的模組 |
| `apps/role-definition/` | 685 角色定義表專用 |
| `apps/employee-entry/` | 686 員工起點對照表專用 |
| `apps/form-route/` | 736 表單路由設定表專用 |
| `adapters/` | 掛在各申請 App 上的程式 |
| `tools/` | 列表頁上的維護工具（健康檢查、模擬器等 11 支） |
| `tests/` | 自動測試，`npm test` 執行 |
| `docs/` | 文件 |
| `presentation/` | 對內分享用的簡報和講稿 |

---

## 文件清單

| 檔案 | 內容 | 什麼時候更新 |
|------|------|-------------|
| `docs/對話脈絡.md` | 設計決策和理由 | 做了重要決定時 |
| `docs/Phase進度追蹤.md` | 進度和待辦 | 每做完一件事 |
| `docs/00-規格書.md` | 架構、模組、對外介面 | 架構有變動時 |
| `docs/02-欄位代碼對照表.md` | 各 App 的欄位 | kintone 欄位有增減時 |
| `docs/05-全方位架構評估報告.md` | 2026-07 的架構健檢和改善項目 | 項目處理完時標記 |
| `docs/06-表單路由與流程標準化設計提案.md` | 表單路由（App 736）和標準流程的設計 | 設計有變動時 |
| `docs/07-代理人功能設計提案.md` | 代理人功能的設計（還沒做） | 開始做代理人時 |
| `docs/09-表單接入與測試手冊.md` | 新表單接入的步驟和測試清單 | 接入流程有變時 |
| `docs/10-工具按鈕盤點與分組.md` | 工具清單、上傳順序、畫面用字 | 新增工具或改上傳順序時 |
| `docs/換機接續開發指南.md` | 換電腦時怎麼接著做 | 很少需要改 |
| `docs/archive/` | 做完的工作清單、驗收清單、舊的實作計畫 | 不再更新 |

還沒寫的文件：`01-HR維護操作手冊`（P2）、`03-應變指南`（P9）、`04-開發者整合指南`（P10）。

**整理文件的習慣**：一份清單或計畫做完了，就移到 `docs/archive/`；提案定案後，內容併進規格書和欄位表。
這樣 `docs/` 裡留下的都是現在還有用的東西。
